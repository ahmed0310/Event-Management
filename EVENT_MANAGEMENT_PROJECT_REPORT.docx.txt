    8. Staff       - Personnel at events

RELATIONSHIPS (11):
    Event ←→ Organizer (1:N) - Organizer manages events
    Event ←→ Venue (M:1) - Events held at venues
    Event ←→ Participant (M:M) - Participants in events
    Participant ←→ Ticket (1:N) - Participant books tickets
    Ticket ←→ Event (M:1) - Tickets for events
    Participant ←→ Payment (1:N) - Participant makes payments
    Payment ←→ Ticket (1:1) - Payment per ticket
    Event ←→ Sponsor (1:N) - Event has sponsors
    Event ←→ Staff (1:N) - Event has staff
    Participant ←→ Staff (M:M) - Interaction tracking

3.2 DATABASE SCHEMA

TABLE: Organizer

    • org_name (UNIQUE)
    • contact_person
    • email
    • phone
    • address

TABLE: Venue
    • venue_id (PK)
    • venue_name (UNIQUE)

    • location
    • contact
    • rental_cost

TABLE: Event
    • event_id (PK)
    • event_name
    • event_date
    • event_time
    • event_type (CHECK IN(...))
    • description
    • budget (CHECK >= 0)
    • venue_id (FK)
    • organizer_id (FK)

TABLE: Participant
    • participant_id (PK)
    • full_name
    • gender (CHECK M/F)
    • email (UNIQUE)
    • phone (UNIQUE)
    • address
    • registration_date

TABLE: Ticket
    • ticket_id (PK)
    • event_id (PK, FK)
    • participant_id (FK)
    • ticket_type (CHECK IN(...))
    • price (CHECK > 0)
    • booking_date
    • status

TABLE: Payment
    • payment_id (PK)
    • ticket_id (FK)
    • participant_id (FK)
    • amount (CHECK > 0)
    • payment_method (CHECK IN(...))
    • payment_date
    • status

TABLE: Sponsor
    • sponsor_id (PK)
    • sponsor_name (UNIQUE)
    • contact_person
    • email
    • contribution
    • event_id (FK)

TABLE: Staff
    • staff_id (PK)
    • staff_name
    • role
    • email (UNIQUE)
    • phone
    • event_id (FK)

5.1 STORED PROCEDURES (4)

PROCEDURE 1: procAddEvent
    Purpose:    Create new event with auto-ID generation
    Parameters: IN - event_name, date, time, type, budget, venue_id, organizer_id
                OUT - new event_id
    Features:   Auto-increment, error handling, transaction control
    Usage:      procAddEvent('Tech Summit', ..., p_id);

PROCEDURE 2: procRegisterParticipant
    Purpose:    Register new participant with validation
    Parameters: IN - full_name, gender, email, phone, address
    Features:   Gender validation (M/F), email uniqueness check,
                named exceptions, meaningful error messages
    Usage:      procRegisterParticipant('Ali Khan', 'M', 'ali@email.com', ...);
    Frontend:   POST /plsql/registerParticipant

PROCEDURE 3: procProcessPayment
    Purpose:    Process payment and update tickets
    Parameters: IN - participant_id, ticket_ids, amount, payment_method
    Features:   Nested procedure call, transaction handling, audit trail
    Calls:      procUpdateTicketBooking (nested call)
    Usage:      procProcessPayment(1, '1,2,3', 15000, 'Card');

PROCEDURE 4: procUpdateTicketBooking
    Purpose:    Update ticket participant and status
    Parameters: IN - participant_id, ticket_ids (comma-separated)
    Features:   String parsing, multiple row updates, exception handling
    Usage:      Called by procProcessPayment

5.2 FUNCTIONS (3)

FUNCTION 1: fnCalculateTotalEventRevenue
    Purpose:    Calculate total revenue for an event
    Parameter:  IN - event_id
    Returns:    NUMBER (Total revenue in PKR)
    Logic:      SUM of payment amounts for booked tickets
    Usage:      SELECT fnCalculateTotalEventRevenue(1) FROM DUAL;
    Frontend:   GET /plsql/eventRevenue/:eventId

    FUNCTION 2: fnGetEventOrganizerName
    Purpose:    Retrieve event organizer name
    Parameter:  IN - event_id
    Returns:    VARCHAR2 (Organizer name or 'Unknown')
    Logic:      JOIN Event and Organizer, return org_name
    Usage:      SELECT fnGetEventOrganizerName(1) FROM DUAL;
    Frontend:   GET /plsql/eventOrganizer/:eventId

FUNCTION 3: fnGetParticipantTicketCount
    Purpose:    Count tickets booked by participant
    Parameter:  IN - participant_id
    Returns:    NUMBER (Ticket count)
    Logic:      COUNT(*) FROM Ticket WHERE participant_id = ...
    Usage:      SELECT fnGetParticipantTicketCount(5) FROM DUAL;
    Frontend:   GET /plsql/participantTickets/:participantId

5.3 TRIGGERS (3)

TRIGGER 1: trgBeforeEventInsert
    Timing:     BEFORE INSERT ON Event
    Purpose:    Auto-generate event ID
    Logic:      SELECT MAX(event_id) + 1, convert name to uppercase
    Features:   Automatic ID assignment, data standardization

TRIGGER 2: trgAfterPaymentUpdate
    Timing:     AFTER UPDATE ON Payment
    Purpose:    Create audit log on status change
    Logic:      Insert record to AuditLog when status changes
    Features:   Audit trail, historical tracking

TRIGGER 3: trgAfterTicketDelete
    Timing:     AFTER DELETE ON Ticket
    Purpose:    Archive deleted tickets
    Logic:      Insert deleted ticket data to TicketArchive table
    Features:   Data preservation, audit trail

5.4 CURSORS (2)

CURSOR 1: Explicit Cursor with OPEN/FETCH/CLOSE
    Name:       cur_event_participants
    Purpose:    Retrieve all participants and their events
    Loop Type:  FETCH-based with NOTFOUND check
    Usage:      
        OPEN cur_event_participants;
        LOOP
            FETCH cur_event_participants INTO ...
            EXIT WHEN cur_event_participants%NOTFOUND;
            -- Process row
        END LOOP;
        CLOSE cur_event_participants;

CURSOR 2: Parameterized Cursor
    Name:       cur_venue_events
    Purpose:    Get all events at a specific venue
    Parameter:  p_venue_id
    Features:   Dynamic filtering, GROUP BY aggregation
    Usage:      FOR rec IN cur_venue_events(5) LOOP ... END LOOP;
    Frontend:   GET /admin/plsql/venueOccupancy/:venueId
