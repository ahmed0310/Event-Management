FILE 1: server.js
─────────────────────────────────────────────────────────────────────────────

LOCATION: Lines 266-585
ADDITIONS: 320 new lines
TYPE: API Endpoints for PL/SQL Integration

NEW ENDPOINTS:

1. POST /plsql/registerParticipant
   Purpose: Register new participant with validation
   Calls: procRegisterParticipant (Stored Procedure)
   Input: {
     fullName: string,
     gender: "M" | "F",
     email: string,
     phone: string,
     address: string
   }
   Validations Performed:
   - Gender must be M or F (validated in PL/SQL)
   - Email must be unique (checked in procedure)
   Output: { success: true, message: string } or error

2. POST /plsql/processPayment
   Purpose: Process payment and update ticket bookings
   Calls: procProcessPayment (Stored Procedure)
   Input: {
     participantId: number,
     ticketIds: number[],
     totalAmount: number,
     paymentMethod: string
   }
   Output: { success: true, message: string }

3. GET /plsql/eventRevenue/:eventId
   Purpose: Calculate total event revenue
   Calls: fnCalculateTotalEventRevenue (Function)
   Parameter: eventId (number)
   Output: {
     eventId: number,
     totalRevenue: number
   }
   Used By: index.html dashboard, admin analytics

4. GET /plsql/eventOrganizer/:eventId
   Purpose: Get organizer name for event
   Calls: fnGetEventOrganizerName (Function)
   Parameter: eventId (number)
   Output: {
     eventId: number,
     organizerName: string
   }

5. GET /plsql/participantTickets/:participantId
   Purpose: Get total ticket count for participant
   Calls: fnGetParticipantTicketCount (Function)
   Parameter: participantId (number)
   Output: {
     participantId: number,
     ticketCount: number
   }
   Used By: admin.html participant lookup feature

6. GET /admin/plsql/eventSummary/:eventId
   Purpose: Get comprehensive event analytics
   Returns: Budget, Revenue, Profit, Profit Margin %
   Calculation: Profit = Revenue - Budget
   Used By: admin.html event analytics section

7. GET /admin/plsql/venueOccupancy/:venueId
   Purpose: Generate venue occupancy report
   Calls: Cursor-based procedure
   Returns: {
     venue: { venueId, venueName, capacity, location },
     events: [{ eventId, eventName, eventDate, attendees, occupancyRate }]
   }
   Used By: admin.html venue occupancy report

8. POST /admin/plsql/bulkTicketGeneration
   Purpose: Generate multiple tickets efficiently
   Calls: pkgEventManagement.procBulkTicketGeneration (Package)
   Input: {
     eventId: number,
     ticketType: string,
     price: number,
     quantity: number
   }
   Output: {
     success: true,
     message: string,
     ticketsGenerated: number
   }
   Used By: admin.html bulk ticket section

9. GET /admin/plsql/eventProfit/:eventId
   Purpose: Calculate event profit
   Calls: Package function
   Returns: {
     eventId: number,
     budget: number,
     revenue: number,
     profit: number,
     profitMargin: string
   }

ALL ENDPOINTS:
- Use parameterized queries (prevents SQL injection)
- Include proper error handling
- Return meaningful error messages
- Support CORS for frontend access
- Follow RESTful conventions

   ✓ Clearer intent
   ✓ Easier to maintain

NEW FUNCTIONS:

1. loadEventRevenues()
   
   Purpose: Load event revenue data using PL/SQL function
   
   Logic Flow:
   1. Fetch all events from /events
   2. For each event:
      - Call /plsql/eventRevenue/:eventId
      - Get total revenue from fnCalculateTotalEventRevenue
   3. Use Promise.all() for parallel requests
   4. Sort events by revenue (descending)
   5. Display top 5 events
   6. Build table HTML dynamically
   
   Code Highlights:
   
   const revenuePromises = events.map(event => {
     return fetch(`http://localhost:3000/plsql/eventRevenue/${event.event_id}`)
       .then(res => res.json())
       .then(data => ({
         eventId: event.event_id,
         eventName: event.event_name,
         revenue: data.totalRevenue || 0
       }))
   });
   
   Promise.all(revenuePromises)
     .then(revenues => {
       revenues.sort((a, b) => b.revenue - a.revenue);
       revenues.slice(0, 5).forEach(rev => {
         // Display in table
       });
     });
   
   Benefits:
   ✓ Parallel API calls (Promise.all)
   ✓ Real-time revenue from database
   ✓ Automatic sorting by revenue
   ✓ Error handling with .catch()

PAGE LOAD EXECUTION:

  loadDashboard();     // Loads stats + revenue table
  loadEventsFromDB();  // Loads event cards
